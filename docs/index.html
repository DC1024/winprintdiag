检测项What it checks

十项检测，一次跑完Ten checks in one pass

关键设计：工具自身不依赖打印服务。打印机、端口、驱动信息直接读注册表，所以服务已经挂掉、队列已经卡死的时候，它照样能跑。 Key design point: the tool does not depend on the print service. Printer, port and driver data is read straight from the registry, so it still runs when the Spooler is down and the queue is jammed.

崩溃历史与出错模块Crash history & faulting module

聚合事件 1000 的 spoolsv 崩溃，按日统计，并直接给出出错模块 —— usbmon.dll 还是 localspl.dll，一眼分辨。Aggregates Event ID 1000 crashes for spoolsv, groups by day, and names the faulting module — usbmon.dll or localspl.dll, at a glance.

崩溃循环判定Crash-loop detection

近 30 分钟崩溃 ≥ 3 次即判定为崩溃循环，并单独统计服务异常终止事件（7031 / 7034）。Three or more crashes within 30 minutes is flagged as a crash loop, alongside SCM abnormal-termination events (7031 / 7034).

组件签名校验Binary signature check

8 个打印核心文件的体积 / 版本 / 修改时间 / 数字签名。签名无效即判定为被第三方替换，并列出 WinSxS 里的正版候选。Size, version, mtime and Authenticode signature of 8 core print binaries. An invalid signature means a third-party replacement — genuine WinSxS candidates are listed.

打印机 / 端口 / 驱动配对Printer · port · driver pairing

每台打印机标注连接方式（USB 直连 / 网络 WSD / 网络 IPP / 网络 IP / 虚拟），并检测端口与驱动错配。Every printer is labelled with its link type (USB / network WSD / network IPP / network IP / virtual) and checked for port-driver mismatches.

重复条目检测Duplicate-entry detection严重critical

识别同一台物理打印机被注册成多个条目。若同时存在 USB 与网络两条通道，直接判为高危。Detects the same physical printer registered multiple times. A USB + network combination is flagged critical.

队列解码Queue decoding

统计队列文件数与体积，解码 .SHD 描述文件里的任务内容 —— 队列卡死时能看到是谁的什么任务。Counts and sizes queue files and decodes job descriptions from .SHD files, so you can see which job is jamming the queue.

变更相关性Change correlation

近 45 天补丁与软件安装、近 30 天意外关机、近 7 天开机次数、蓝屏转储数量 —— 把"什么时候开始坏的"对上"那时候装了什么"。Patches and software from the last 45 days, unexpected shutdowns in 30, boot count in 7, dump count — matching "when it broke" against "what was installed then".

证据窗口Evidence window

报告日志能回溯多远、日志容量是否已满 —— 决定你能不能从历史里找到线索，而不是白翻一遍。How far back the logs reach and whether they are full — so you know the history is actually searchable.

可选修复，先备份后动手Optional repair, backup first

还原被替换的组件时把原文件隔离而非删除；清理队列时把整个目录移动到带时间戳的备份文件夹。Replaced binaries are quarantined, not deleted; clearing the queue moves the whole directory into a timestamped backup.

默认只读Read-only by default

不加开关就绝不改动系统。修复能力必须显式传参且需要管理员权限。Without an explicit switch, nothing on the system is touched. Repair requires both a flag and elevation.

设计取舍Design trade-off

宁可漏报，不可误报Prefer a miss over a false alarm

判定「同一台打印机是否注册了多个条目」时，工具从打印机名 + 端口名提词，只认长度 ≥ 5 且同时含字母和数字的共有词（如 13cedd、m6200nw、l2350dw）。 To decide whether two printer records are the same device, the tool extracts tokens from the printer name + port name and only accepts shared tokens that are at least 5 characters and contain both letters and digits (13cedd, m6200nw, l2350dw).

于是不会发生这种误报So this never happens

把 Adobe PDF、PDF-XChange、PDF24、导出为 WPS PDF 这些虚拟打印机凑成一对 —— 只因为它们名字里都有 pdf。Pairing up virtual printers such as Adobe PDF, PDF-XChange, PDF24 and a WPS PDF printer just because they all contain "pdf".

代价：HP LaserJet 1020 (Copy 1) 与 (Copy 2) 这类同型号重复副本会漏报。这是刻意的 —— 诊断工具误报比漏报更快失去信任。规则由 19 条回归测试兜底，测试直接从主脚本抽取函数原文运行，不会出现「改了主脚本忘改测试」。The cost: same-model duplicates like HP LaserJet 1020 (Copy 1) and (Copy 2) are missed. That is deliberate — a diagnostic tool loses trust faster from false alarms. 19 regression tests guard the rules, and they extract the real function bodies from the main script so they can never drift.

FAQ

常见问题Frequently asked

会不会误删我的打印机或文件？Will it delete my printers or files?

不会。诊断阶段纯只读。-ClearQueue 是把队列文件移动到备份目录，-Repair 是把可疑组件隔离而非删除 —— 两者都保留原件。No. Diagnosis is strictly read-only. -ClearQueue moves queue files into a backup folder, and -Repair quarantines the suspect binary instead of deleting it. Both keep the original.

需要联网吗？要装什么吗？Does it need internet or any installation?

都不需要。单文件、零依赖，只用 Windows 自带的 PowerShell 5.1。Neither. Single file, zero dependencies — only the PowerShell 5.1 that ships with Windows.

打印服务已经挂了，还能跑吗？My spooler is already dead — can it still run?

能，这正是它的核心设计。打印机、端口、驱动信息直接读注册表，不经过打印服务。Yes — that is the core design. Printer, port and driver data comes from the registry, not from the print service.

图形界面打不开怎么办？The GUI won't open — what now?

运行 WinPrintDiag-GUI.cmd，exe 启动失败时它会自动回落到脚本方式。Run WinPrintDiag-GUI.cmd; it falls back to the script when the exe fails to start.

我改了脚本，中文变成乱码了？I edited the script and the text turned into garbage.

.ps1 必须保存为 UTF-8 带 BOM。PowerShell 5.1 会把没有 BOM 的脚本按 ANSI 解码，中文字面量随之损坏 —— 而且报错会伪装成语法错误（意外的标记 / 字符串缺少终止符）。遇到这种「莫名语法错误」，先检查 BOM。.ps1 files must be saved as UTF-8 with BOM. PowerShell 5.1 decodes BOM-less scripts as ANSI, corrupting non-ASCII literals — and the resulting error looks like a syntax error (unexpected token / string is missing the terminator). On a bizarre syntax error in a Chinese script, check the BOM first.

支持哪些系统？Which systems are supported?

Windows 10 / 11 + PowerShell 5.1。部分机器不记录服务启停事件（7036），此时「最近状态」显示不可用，崩溃循环判定改由崩溃次数承担。Windows 10 / 11 with PowerShell 5.1. On machines that don't record service start/stop events (7036), "recent state" shows as unavailable and crash-loop detection falls back to crash counts.
